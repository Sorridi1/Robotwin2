## 训练命令

在现有 maniflow 环境，从仓库根目录执行。以下命令启动正式训练，本次仅验证解析，没有替用户启动该训练。

```bash
cd /home/ljj/code/Robotwin2
conda activate maniflow

FPO_RUN_DIR=/media/Elements1/ljj/ManiFlow/outputs/place_empty_cup-fpopp-0428_seed0

CUDA_VISIBLE_DEVICES=0 bash RoboTwin/policy/FPOpp/train.sh \
  --checkpoint /media/Elements1/ljj/ManiFlow/outputs/place_empty_cup-maniflow_pointcloud_policy_robotwin2-0428_seed0/checkpoints/epoch=0500-val_loss=0.373935.ckpt \
  --task-name place_empty_cup --task-config demo_messy_ur5 --seed 0 \
  --output-dir "$FPO_RUN_DIR" \
  state_key=ema_model \
  max_iterations=100 total_action_steps=400000 \
  actor.intermediate_clip=1.5 actor.final_action_clip=1.0 \
  validation.interval=20 validation.run_final=true validation.episodes=100 \
  validation.seed_file=/media/Elements1/ljj/ManiFlow/outputs/eval_scene_seeds_validation_shared.json
```

使用4个并行环境，每轮64个 chunk，最多100轮或40万实际动作，以先达到者结束。当前有效窗口最多15步，100轮的动作上界为384000，所以此命令不会因默认10万动作预算而提前结束。保持与本工作当前 RL 配置相同的1.5中间裁剪、1.0最终裁剪；FPO++ 的 ratio/clip 系数采用自己的配置，不将其与高斯链 ratio 的数值尺度等同。

每轮保存最新训练状态；每20轮及最后一轮，在100个 validation 场景上评估并按成功率更新 best。validation seed 文件是所有方法共享的验证源，不是模型结果目录，也不用于最终 test。比较双方时，需使用相同筛选模式、同一验证池和同一最终测试池。

## 输出与不覆盖规则

全部本次训练结果位于新的 `$FPO_RUN_DIR`，不会写回原始0428目录或其它方法目录：

```text
place_empty_cup-fpopp-0428_seed0/
  .hydra/config.yaml
  metrics.jsonl
  training_scene_seeds.json
  checkpoints/
    latest.ckpt                   # 完整续训状态，也可评估
    best.ckpt                     # 验证集最优 actor，不能续训 optimizer
  eval_results/
    epoch_20/scene_rl/
    epoch_40/scene_rl/
    ...
  evaluation_retries/             # 同轮次评估重试时使用新子目录
```

评估目录内保存 `_result.txt`、`_scene_selection.json`、`_fpopp_protocol.json` 和视频。同一轮次/同一模式已有结果或评估标记时，独立评估会拒绝覆盖，需显式指定新的 `--eval_output_dir`。训练内的重复评估会自动分配 `evaluation_retries/epoch_N_随机标识/`，保留先前报告与日志。

## 与本工作保存逻辑的对应

保存策略是相同的“最新状态 + 验证最优 actor”，命名和文件格式不完全相同：

| 用途 | 本工作 | FPO++ |
|---|---|---|
| 完整断点续训 | `latest_rl.ckpt` | `latest.ckpt` |
| 最新 actor 评估 | `latest.ckpt` | 同一份 `latest.ckpt` 中的 actor |
| 验证集最优 actor | `best.ckpt` | `best.ckpt` |
| 周期与结束评估 | 每20轮及最后一轮（启用时） | 上述命令同样如此 |

两边都不是默认永久保留每一轮独立权重。`latest.ckpt` 会在本次 run 内更新，`best.ckpt` 仅在验证成功率严格提升时更新；这与保留历史评估报告是两回事。FPO++ 在周期评估前保存完整最新状态，评估成功后再保存 best 分数；评估程序异常不会丢失已完成的更新。

FPO++ 的完整状态包含模型、normalizer、critic、两个 optimizer、AMP scaler、奖励缩放、迭代/动作计数、训练 seeds、RNG 和下一批场景 seed。与原 ManiFlow 部署文件格式不同，请使用 FPOpp 的训练与评估入口。

恢复命令：

```bash
CUDA_VISIBLE_DEVICES=0 bash RoboTwin/policy/FPOpp/train.sh \
  --resume "$FPO_RUN_DIR/checkpoints/latest.ckpt"
```

## 最终测试

使用独立且所有方法共享的 test bank；每次测试指定新的输出子目录。以下时间标签保证正常使用时各次测试分开；目录碰撞仍会报错，不覆盖。

```bash
FPO_TEST_DIR="$FPO_RUN_DIR/test_evaluations/$(date +%Y%m%d_%H%M%S)"

bash RoboTwin/policy/FPOpp/eval.sh \
  "$FPO_RUN_DIR/checkpoints/best.ckpt" \
  place_empty_cup demo_messy_ur5 10 0 \
  --eval_num_episodes 100 --eval_scene_selection rl \
  --eval_scene_seed_file /media/Elements1/ljj/ManiFlow/outputs/eval_scene_seeds_test_shared.json \
  --eval_output_dir "$FPO_TEST_DIR"
```

结果位于 `$FPO_TEST_DIR/eval_results/epoch_N/scene_rl/`，其中N是 best 模型的微调迭代数。它不会覆盖训练验证结果或旧方法结果。实际 train/validation/test seeds 还需检查无交集；程序会检查当前模型与已有评估池的训练 seed 交集，新池应在最终汇总时核对。
